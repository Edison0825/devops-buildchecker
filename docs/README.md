# 文档与证据约定

本目录保存课程说明、个人实验报告和验收记录。课程提交分支中的个人报告应保留报告人的真实身份，并把组内其他成员的工作明确标为既有成果，不把他人的测试、PR、代码修改或镜像构建重新归属给当前报告人。

## 文件命名

- `E5_<轨道>_<项目>_复现说明.md`：E5 原始复现和证据链说明。
- `E6_<轨道>_<项目>_MVP说明.md`：E6 实现、缺陷样例和修复复检说明。
- `实验报告.md`：当前课程提交版本的个人报告；报告身份、贡献边界和证据索引必须与所在分支一致。
- `验收记录.csv`：沿用课程表头，追加个人验收项时保留已有记录，不编造不存在的 trace、提交或结果。

已有文件名不因仓库整理直接改名，以免破坏课程提交、外部链接或组内引用。新增文档按上述前缀和用途命名。

## 证据边界

- `work/` 仅保存运行证据、日志、artifact 和云主机导出结果，默认忽略，不随普通代码或文档提交。
- 实验 ZIP、云主机证据和备份文件应单独保存；报告可以引用相对路径，但不应为了让路径存在而把运行证据塞回 Git。
- 如果课程明确要求提交某份证据，应在评审前单独确认范围，再使用 `git add -f` 精确加入指定文件。

## 提交前检查

1. 确认当前分支不是 `main`，且报告身份与学号分支一致。
2. 检查报告中的证据路径、提交 SHA、镜像 ID 和贡献归属；无法在当前仓库核对的内容应标为组内已有证据。
3. 确认 `.idea/`、`.venv/`、`pyproject.toml`、`uv.lock`、缓存和 `work/` 没有被 Git 跟踪或暂存。
4. 运行测试和 `python3 scripts/secret_scan.py . --history`，最后只提交本次整理范围内的文件。

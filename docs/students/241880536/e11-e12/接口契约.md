# 接口契约（实现同步版）

文档归属：241880536（沿用原作者目录归属）。2026-11-16 按 `main@9550114` 的 `labs/e11e12/server.py`、`labs/e11e12/pipeline.py` 与 `run_e11e12.py` 同步；本次仅静态阅读代码核对，不代表新增实测。

对象：`python3 run_e11e12.py serve --port 18080`。`--port` 指定宿主端口，映射为 `-p 127.0.0.1:18080:8080`，容器内仍监听 8080；省略参数或指定 `--port 8080` 时宿主端口为 8080。远端使用宿主端口 18080 时，可用 `ssh -L 18080:127.0.0.1:18080 <远端主机>` 转发。

Schema：`e11e12-1`。提交请求体为 JSON；下述 JSON 响应的 `Content-Type` 为 `application/json; charset=utf-8`，文件下载成功响应除外。

## 提交任务 POST /v1/jobs

请求结构（字段层级示意，路径与 revision 须替换为实际值）：

```json
{
  "idempotency_key": "example-key",
  "input": {
    "mode": "e11-a",
    "repo": "/course/data/example",
    "base": "<base revision>",
    "target": "<target revision>"
  }
}
```

| 项               | 说明                                                                                                                                                                              |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外层字段         | `idempotency_key`：非空字符串，≤128 字符；`input`：JSON 对象                                                                                                                      |
| `input` 基本字段 | `mode`（`e11-a` / `e11-b` / `e12`）、`repo`、`base`、`target`；不是 `base_commit` / `target_commit`                                                                               |
| 路径约束         | `repo` 以及提供时的 `candidate`、`fixed_report`，解析后的路径必须在 `/course/data` 下；路径存在性、仓库和报告内容等在执行阶段检查                                                 |
| 模式相关输入     | `e11-b` / `e12` 执行需要 `candidate`（Dockerfile）；`e11-b` 还需要 `fixed_report`（`kind="fixed-md"` 的阶段信封）                                                                 |
| 其他执行参数     | `expected_output`、`link_target`、`build_command`、`clean_command`、`header`、`header_after`、`header_expected`、`header_edits`、`build_timeout`，均放在 `input` 内               |
| 成功受理         | **202**，返回任务状态对象，含 `schema_version`、`job_id`、`status`、`idempotency_key`、`request_hash`；新任务初始为 `QUEUED`，响应时也可能已被 worker 更新为 `RUNNING`            |
| 幂等             | 同 `idempotency_key` + 同 `input` → **202**，返回同一个 `job_id` 的当前状态，不重复执行；哈希基于按键排序序列化的整个 `input`                                                     |
| 冲突             | 同 `idempotency_key` + 不同 `input` → **409** `{"error":"IDEMPOTENCY_CONFLICT"}`                                                                                                  |
| 越界             | 例如 `repo` 不在 `/course/data` → **400** `{"error":"repo must be under /course/data"}`                                                                                           |
| 同步校验失败     | 请求长度须为 1..65536 字节；JSON 解析错误、缺少外层字段、`input` 非对象、幂等键不合法、未知 `mode`、缺少非空的 `repo/base/target` 等，被处理为 **400** `{"error":"<错误字符串>"}` |

`candidate` / `fixed_report` 的缺失并没有对应的提交前必填校验，不能承诺返回 400。请求通过同步检查后，worker 中的缺字段、文件读取、报告校验或构建等错误属于**异步任务失败**，须查询任务状态；不能用 POST 的 202 判断流水线成功。

## 查询任务 GET /v1/jobs/{job_id}

| 项       | 说明                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------------- |
| 进行中   | **200**，`status` 为 `QUEUED` / `RUNNING`（字段不是 `state`）                                                     |
| 结束     | **200**，`status` 为 `SUCCEEDED` / `FAILED` / `TIMED_OUT`；若执行结果提供了 `trace_id`、`error`，也会写入状态对象 |
| 失败信息 | 任务状态中的 `error` 是 `{"code":"…","message":"…"}` 对象；与 HTTP 错误响应的 `error` 字符串不同                  |
| 职责     | 仅返回持久化的任务状态对象，不内嵌 `result`、`stages` 或产物清单；完整结果另查 `/artifacts`                       |
| 不存在   | **404** `{"error":"NOT_FOUND"}`                                                                                   |

流水线内捕获的异常一般形成 `FAILED`，`subprocess.TimeoutExpired` 形成 `TIMED_OUT`；错误码随失败点而异，例如 `STALE_REPORT`、`UNSUPPORTED_PROJECT`、`DRAFT_FAILED`、`REPAIR_REJECTED`、`EXECUTION_FAILED`，并非固定穷举。若异常逃出 `execute()`，服务 worker 将任务置为 `FAILED`，附 `{"code":"WORKER_FAILED","message":"<异常信息>"}`；此时不保证生成 `result.json`。

## 完整结果与产物清单 GET /v1/jobs/{job_id}/artifacts

- **200**：读取并返回该任务 `evidence/result.json` 的整个对象，不只是 `artifacts` 数组。
- 结果包含 `schema_version`、`job_id`、`trace_id`、`status`、`stages`、`artifacts`；成功解析两个 revision 后还包含 `base_commit`、`target_commit`，失败时可包含 `error`。
- `stages` 记录已成功写出的阶段，元素为 `{"name":"full-check","artifact":{"uri":"artifact://job-…/full-check.json","sha256":"…","bytes":3632}}`（字节数仅示意）。阶段依模式为 `draft`、`full-check`、`incremental-check`、`fixed-md`、`repair`、`recheck` 的相应子集；失败时可能只有部分阶段或空数组。
- 顶层 `artifacts` 是 `{"uri":"artifact://job-…/<相对路径>","sha256":"…","bytes":123}` 的列表，元素**没有 `kind` 字段**。清单在写入 `result.json` 前扫描 `evidence` 下的文件生成，排除 `.git` 路径和符号链接；正常首次生成的清单不包含 `result.json` 自身。
- **409** `{"error":"RESULT_NOT_READY"}`：`result.json` 尚不存在。这是文件存在性判断，不能等同于“任务仍在运行”；worker 异常或服务重启后的失败任务也可能没有该文件。已生成结果的失败任务仍可返回 200。
- 任务不存在：**404** `{"error":"NOT_FOUND"}`。

## 取文件 GET /v1/jobs/{job_id}/files/{path}

- **200**：返回 `evidence` 下文件的原始字节，`Content-Type: application/octet-stream`，**不是 JSON 响应**（即使下载文件内容本身是 JSON）。
- 响应头 `X-Content-SHA256: <hex>` 为实际返回字节的 SHA-256；文件未变化时应与清单中的 `sha256` 一致。
- `artifact://<job_id>/<相对路径>` 对应 `/v1/jobs/{job_id}/files/<相对路径>`，URI 本身不是 HTTP 下载地址。
- **404** `{"error":"NOT_FOUND"}`：任务不存在、文件不存在或不是普通文件、解析后路径越出该 job 的 `evidence` 目录（例如 `../../etc/passwd`），或命中 `.git` 路径组件。

## 阶段信封字段

阶段 JSON 文件（不是任务状态对象，也不是顶层完整结果）采用以下结构：

`{"schema_version":"e11e12-1","job_id":"job-<uuid32>","trace_id":"trace-<uuid32>","kind":"draft|full-check|incremental-check|fixed-md|repair|recheck","commit":"<40 hex>","status":"SUCCEEDED","data":{…},"artifacts":[{"uri":"artifact://job-…/<相对路径>","sha256":"…","bytes":123}]}`

- `full-check` 的 `commit` 为解析后的 base，其余生成阶段为解析后的 target；`check_envelope()` 在调用处校验 schema、预期 commit、成功状态以及可选的 kind，不匹配可抛 `SCHEMA_MISMATCH`、`STALE_REPORT`、`UPSTREAM_FAILED`、`ARTIFACT_TYPE_MISMATCH`。
- `e11-b` 的 `fixed_report` 须为 target 对应、状态成功的 `fixed-md` 信封，且 `data.commit` 也须匹配 target；这些检查发生在 worker 执行中。
- 信封内的 `artifacts` 列出该阶段相关文件；完整结果中的 `stages[].artifact` 则指向信封文件本身。

## 健康检查 GET /health

**200** `{"status":"ok","schema_version":"e11e12-1"}`。

## 重启语义

状态持久化在 `work/api-jobs/job-*/state.json`。服务启动时把持久化的 `QUEUED` / `RUNNING` 任务改为 `FAILED`，写入 `error={"code":"SERVER_RESTARTED","message":"Resubmit with a new key"}`，不会自动恢复执行；已结束任务（`SUCCEEDED` / `FAILED` / `TIMED_OUT`）的状态保持不变，已有结果文件仍可读。

幂等键索引也从状态文件恢复，因此用原键、原输入重提只会返回原任务；需用新键重新提交。

## 运维注意

- `data/` 已在 `.gitignore`，仓库内只保留 `data/integration-sample` 的生成说明与真实项目清单；容器内路径一律 `/course/...`。
- `serve` 需要挂 `/var/run/docker.sock` 与 `--group-add <sock gid>`（DRAFT 阶段要构建候选镜像）。
- 停止服务用 `docker rm -f <container>`，只 `pkill` 包装进程会造成「容器仍在跑」的假状态。

# 接口契约（实测版）

对象：`run_e11e12.py serve --port 8080`（容器内 8080，`-p 127.0.0.1:18080:8080`；远端用 `ssh -L 18080:127.0.0.1:18080` 转发）
Schema：`e11e12-1`　　所有请求体与响应体均为 JSON（`Content-Type: application/json`）

## 提交任务 POST /v1/jobs

| 项 | 说明 |
|---|---|
| 请求字段 | `key`（幂等键，≤128 字符）、`mode`（`e11-a` / `e11-b` / `e12`）、`repo`（必须在 `/course/data` 下）、`base_commit`、`target_commit`、`candidate`（Dockerfile，必须在 `/course/data` 下）、`fixed_report`（`e11-b` 必填）、`expected_output`、`link_target`、`build_command`、`clean_command`、`header`、`header_edits`、`build_timeout` |
| 成功 | **202** `{"job_id":"job-…","state":"QUEUED"}` |
| 幂等 | 同 `key` + 同输入 → 返回**同一个** `job_id`，不重复执行 |
| 冲突 | 同 `key` + 不同输入 → **409** `{"code":"IDEMPOTENCY_CONFLICT"}` |
| 越界 | `repo` 不在 `/course/data` → **400** `{"error":"repo must be under /course/data"}` |
| 校验失败 | `mode` 不在枚举、`key` 超长、`fixed_report` 缺失 → **400** |

## 查询任务 GET /v1/jobs/{job_id}

| 项 | 说明 |
|---|---|
| 进行中 | 200，`state` ∈ `QUEUED` / `RUNNING` |
| 完成 | 200，`state="SUCCEEDED"`，`result` 为 `result.json`（含 `stages[].artifact{uri,sha256,bytes}`） |
| 失败 | 200，`state="FAILED"`，`error.code` ∈ `MISSING_MAKE`、`STALE_REPORT`、`UNSUPPORTED_PROJECT`、`UNSUPPORTED_FLAGS`、`DRAFT_FAILED`、`REPAIR_REJECTED`、`SERVER_RESTARTED`、`EXECUTION_FAILED` |
| 不存在 | **404** `{"code":"JOB_NOT_FOUND"}` |

## 产物清单 GET /v1/jobs/{job_id}/artifacts

- 200：`{"job_id":…,"artifacts":[{"kind":"full-check","uri":"artifact://job-…/full-check.json","sha256":"…","bytes":3632}, …]}`
- 未完成：**409** `{"code":"RESULT_NOT_READY"}`

## 取文件 GET /v1/jobs/{job_id}/files/{path}

- 200：原始字节，响应头 `X-Content-SHA256: <hex>` 与清单 `sha256` 一致
- **404**：路径越界（`../../etc/passwd`）或命中 `.git`
- **404**：`path` 不在该 job 的 `out` 目录内

## 信封字段

`{"schema_version":"e11e12-1","job_id":"job-<uuid32>","trace_id":"trace-<uuid32>","kind":"draft|full-check|incremental-check|repair|recheck","commit":"<40 hex>","status":"SUCCEEDED","data":{…},"artifacts":[…]}`

- `kind=full-check` 时 `commit` = base，其余阶段 = target；不一致由 `check_envelope()` 抛 `STALE_REPORT`。
- `artifact://<job_id>/<相对 out 的路径>` 必须能被 `/files/` 解析，且哈希与清单一致。

## 重启语义

服务启动时把持久化的 `QUEUED`/`RUNNING` 任务改为 `FAILED`（`code=SERVER_RESTARTED`，`message="Resubmit with a new key"`）；已完成任务的结果仍可读。

## 运维注意

- `data/` 已在 `.gitignore`，仓库内只保留 `data/integration-sample` 的生成说明与真实项目清单；容器内路径一律 `/course/...`。
- `serve` 需要挂 `/var/run/docker.sock` 与 `--group-add <sock gid>`（DRAFT 阶段要构建候选镜像）。
- 停止服务用 `docker rm -f <container>`，只 `pkill` 包装进程会造成「容器仍在跑」的假状态。

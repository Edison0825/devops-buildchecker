# ADR：增量复用粒度与报告版本绑定

编号、日期、作者：ADR-267-01，2026-11-15，241880267

问题：E11-A 要求说明增量检测中哪些目标刷新、哪些复用；E12 要求报告与修复目标提交一致。需要确认现有实现的实际行为，而不是凭印象描述。

候选方案：
1. 按单个目标细分失效：只刷新依赖变化文件的目标。
2. 保持现有保守策略：缓存 key 变化则全部刷新，否则全部复用。
3. 不写测试，仅在报告里文字说明。

采用方案与原因：采用方案 2，并为其补测试（不改 `lab.py`）。阅读 `lab.scan()` 可知 key 由本地 `#` 预处理行、源文件集合、Makefile 配方和编译参数组成，任一变化即整体失效。此策略可能多刷新，但不会漏刷新，在教学接口下行为可预期；方案 1 需要先建模头文件到目标的传递关系，超出本次范围。方案 3 无法防止后续改动破坏该行为。

输入输出字段：输入为旧报告的 `key`、`actual`、`findings` 与当前工作副本；输出为 `refreshed`、`reused`、`added`、`resolved`。报告绑定 `commit`，`patch()` 发现报告 commit 与工作副本 HEAD 不一致时抛 `STALE_REPORT`。

兼容性与测试：`labs/e11e12/test_student_241880267.py` 共 3 项（仅改函数体全部复用；新增 `#include` 全部刷新；旧报告修补新提交触发 `STALE_REPORT`）。本机（macOS，Apple clang）和服务器（gcc，全部 23 项）均通过。若将来改为按目标细分失效，测试 1、2 需同步修改，这是有意的变更信号。

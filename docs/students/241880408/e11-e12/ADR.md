# ADR：集成接口决策

编号、日期、作者：ADR-241880408-E11E12-01 / 2026-11-10 / 刘智健（AI代理辅助，见AI_USAGE）。

问题：保留E8–E10接口和历史的前提下，衔接真实全量图、历史缓存、补丁消费及HTTP任务；本组真实项目、B组协作安排尚未确定。

候选方案：立即更换所有解析接口；保留受限接口并补契约/恢复验证；把固定样例当真实项目交付。

采用方案与原因：保留课程参考pipeline/server/旧lab.py接口，新增个人契约测试和实际HTTP自测。仅完成可独立推进的范围，将真实项目和B组共同验收显式保持PENDING，避免把生成样例或个人自测误记为联合验收。

输入输出字段：沿用e11e12-1；基线full-check绑定base，其余绑定target；全链路job_id/trace_id一致。消费artifact前核对URI所属job、SHA256、kind、status和commit。对幂等冲突、旧报告、哈希变更及重启状态按文档拒绝/恢复。

兼容性与测试：原10项契约测试+新增4项；A组全量/增量对照、E12五阶段、同键/冲突、下载哈希及真实重启。未改变E7/E8–E10源文件或原必需检查；真实项目命名和输出不符时仍需单独适配。

网络决策：首轮候选下载依赖超时，另存仅调整源、IPv4和超时参数的候选，保留原digest和项目构建/运行指令；原失败目录留存，使用新OUT重跑，不将下载故障充作预期缺make或成功。

服务生命周期：仅用本机127.0.0.1端口，个人自测结束停止自己创建的服务；后续B组按接口文档重新启动并SSH转发，不预留无监控的长期进程。
